# Equivalent (Homogenized) Elastic Properties of a Perforated Tube Support Plate (Abaqus/CAE)

**Goal:** Build a finite element model of a representative rectangular region of the perforated TSP with **explicitly meshed holes**, run a **two-step displacement-controlled analysis** (pull in X, then pull in Y), and use the resulting reaction forces and transverse displacements to calculate the **equivalent orthotropic elastic constants** — `Ex, Ey, Ez, ν_xy, ν_xz, ν_yz, Gxy, Gxz, Gyz` — so the full TSP (1000s of holes) can be modeled as a homogeneous orthotropic plate with no explicit holes.

**Your setup (as confirmed):**
- TSP: **1 in thick**, flat, repeating **triangular (60° staggered) pitch** hole pattern.
- In-plane constants come from the FE model (reaction force + Poisson displacement of the coupled edges); out-of-plane constants come from a **hand calc** on the net/gross area ratio.
- Each plate edge is **kinematically coupled** to a reference node at the mid-point of that edge; BCs are applied only to the reference nodes.
- Abaqus/CAE GUI walkthrough, with the resulting `.inp` keyword blocks shown at the key steps so you can verify the deck.
- Formulas keep **`##` placeholders** for you to fill in from your geometry and results.
- Units: **in, psi, lbf** (consistent — no unit conversions needed inside Abaqus).

> **Back up / bookkeeping.** Keep the region dimensions, hole count, and every extracted number in a small calc sheet as you go — the property extraction is a hand calc layered on FE output, and a reviewer will want to trace each `##`.

---

## Overview of the flow

1. Choose the representative region (triangular-pitch specifics below) and record its dimensions.
2. Build the part: rectangular solid, 1 in thick, holes cut by a patterned sketch.
3. Define the base (unperforated) material and assign a solid section.
4. Assembly: instance the part and create 4 reference points (RPs) at the mid-point of each edge.
5. Create node/geometry sets for the 4 edge faces and the 4 RPs.
6. Kinematically couple each edge face to its RP (DOF table below — note the corner-node fix).
7. Create two static steps and the per-step BCs on the RPs.
8. Mesh (ligament-controlled seeding), request history output of `U` and `RF` at the RPs.
9. Datacheck, then run.
10. Extract `Fx`, `Uxy` (Step 1) and `Fy`, `Uyx` (Step 2) from history output.
11. Hand-calc the equivalent constants (all formulas below, with `##` placeholders).
12. Enter the constants in Abaqus as an orthotropic material (Engineering Constants) for the full TSP model.
13. Validate (solid-plate benchmark, equilibrium, reciprocity, convergence, ASME A-8000 cross-check, round-trip model).

Two variant sections after Step 13 cover **building the extraction model from S4R shells** (when that's appropriate and the exact model deltas) and **thickness applicability** (the 1-in TSP vs an 11-in-thick plate).

> **First run the whole procedure on a plate with NO holes.** With the couplings and BCs built correctly, the extraction must return `Ex = Ey = E` and `ν_xy = ν` (0.3) almost exactly. This is the cheapest way to debug the couplings/BCs before the perforated geometry complicates the picture. See **Validation, check 1**.

## Step 0 — Choose the representative region (triangular pitch)

Define the pattern parameters first:

| Symbol | Meaning | Value |
|--------|---------|-------|
| `D` | Hole diameter | `##` in |
| `P` | Pitch (center-to-center, same in all three 60° directions) | `##` in |
| `b = P − D` | Minimum ligament width | `##` in |
| `η = (P − D)/P` | Ligament efficiency | `##` |
| `Lz` | Plate thickness | 1 in |

For a triangular pattern with rows running along X: rows are spaced `√3·P/2` apart in Y, and alternate rows are offset `P/2` in X.

**Pick the region boundaries on symmetry lines of the pattern.** The clean choice is to put all four boundaries through **hole centerlines**:

- `Lx = m·P` (m = whole number of pitches in X)
- `Ly = n·√3·P` (n = whole number of double-rows in Y)
- Corners land on hole centers → **quarter holes at the 4 corners, half holes along the edges, full holes inside.**

This makes the region exactly periodic and mirror-symmetric, so the straight-edge (coupled) boundary condition is consistent with how the region actually sits inside the infinite pattern. The **effective hole count** is then simply:

```
N_eff = 2·m·n          (2 holes per P × √3·P cell, counting the fractional holes)
```

**Size:** use enough pitches that the answer is pattern-driven, not edge-driven — `m` and `n` giving roughly **4–6 pitches in each direction** and a near-square region (`Lx ≈ Ly`) is typical. (With properly coupled straight edges even a single unit cell is close, so a few pitches is comfortably converged — your mesh-convergence check will confirm.)

Record the equivalent-plate dimensions and **gross** section areas:

```
Lx = ## in      Ly = ## in      Lz = 1 in

Ax = Ly · Lz = ## in²      (gross area normal to X)
Ay = Lx · Lz = ## in²      (gross area normal to Y)
Az = Lx · Ly = ## in²      (gross area normal to Z)
```

and the **net** area normal to Z (material actually present in plan view):

```
A_net,z = Lx·Ly − N_eff · (π·D²/4) = ## in²
```

> **Gross vs net — the single most common bookkeeping error in this calc.** The equivalent plate is *unperforated*, so the in-plane moduli `Ex`, `Ey` are computed with the **gross** areas `Ax`, `Ay` (that's the whole point — the stiffness knock-down lives in the modulus, not the area). The net area appears only in the out-of-plane ratio `Ez = E·(A_net,z / Az)`.

> **Note vs your write-up:** the write-up describes holes "aligned in the X-Y axis" (a square pattern); you've confirmed the actual TSP pattern is triangular. Everything in this walkthrough is written for triangular pitch — only Step 0 (region choice, `N_eff`) and the expected degree of `Ex` vs `Ey` anisotropy change between the two patterns. For triangular pitch, take **X along the hole rows**; `Ex` and `Ey` will come out close but not identical, which is exactly what the orthotropic material is for.

## Step 1 — Part: rectangular solid with patterned holes

**Part module:**

1. `Part > Create`: 3D, Deformable, Solid, Extrusion. Sketch a rectangle from `(0, 0)` to `(Lx, Ly)`; extrude depth `1.0` (so the part occupies `z = 0` to `z = 1`). Working with the part corner at the origin keeps every coordinate in this walkthrough literal.
2. `Shape > Cut > Extrude`, sketch on the top face (or the `z = 0` face — either works, cut **Through All**):
   - Sketch one circle of diameter `D` at a hole-center location, e.g. `(0, 0)`.
   - `Add > Pattern` (linear pattern), **Direction 1:** spacing `P`, count `m + 1` along X.
   - Select that whole row, pattern again, **Direction 2:** spacing `√3·P`, count `n + 1` along Y → this creates all the *even* rows (the ones whose centers sit at `x = 0, P, 2P, …`).
   - Sketch one more circle at `(P/2, √3·P/2)` and pattern it the same way (`m` columns × `n` rows) → the *odd* (staggered) rows.
   - Circles centered on the region boundary simply cut half/quarter holes — that is intended.
3. Confirm in the viewport: quarter holes at corners, half holes along all four edges, staggered full holes inside.

> **Shell / 2D alternative:** since the in-plane extraction is a plane-stress (membrane) problem, the extraction model can equally be built from **S4R shell elements** (or a CPS8R plane-stress mesh) and give the same `Ex, Ey, ν_xy` for less modeling effort — see **"Variant — S4R shell extraction model"** after Step 13 for the exact deltas and the cautions. The main walkthrough stays with the 3D solid per your procedure; the thickness question (1 in vs 11 in) is treated in **"How thick can the plate be?"**, also after Step 13.

## Step 2 — Property: base material and section

**Property module:**

1. `Material > Create`, e.g. `TSP-BASE`: `Mechanical > Elasticity > Elastic`, Isotropic:

   ```
   E = ## psi        ν = 0.3
   ```

   (Abaqus computes `G = E / (2·(1+ν)) = ## psi` internally for the isotropic base material — you'll use this same formula in the hand calc for the equivalent shear moduli.)
2. `Section > Create`: Solid, Homogeneous → material `TSP-BASE`.
3. `Assign > Section` to the whole part.

Use E at the temperature your equivalent properties will be reported at. If you need the equivalent properties at several temperatures, the geometry knock-down factors (`Ex/E`, `Ey/E`, …) are temperature-independent — extract them once and scale by `E(T)`.

2. `Tools > Reference Point`, four times, at the mid-point of each edge, mid-thickness:

| RP name | Location (x, y, z) | Edge it will control |
|---------|--------------------|----------------------|

| `RP-R` | `(Lx,   Ly/2, 0.5)` | Right face (`x = Lx`) |
| `RP-B` | `(Lx/2, 0,    0.5)` | Bottom face (`y = 0`) |
| `RP-T` | `(Lx/2, Ly,   0.5)` | Top face (`y = Ly`) |

3. Rename each RP as above (`Tools > Reference Point Manager` / model tree → Features) so the history output is self-documenting.

## Step 4 — Sets and surfaces

**Assembly-level sets** (`Tools > Set > Create`):

1. `SET-RP-L`, `SET-RP-R`, `SET-RP-B`, `SET-RP-T` — one per reference point (needed for the history output requests and keyword-level BCs).
2. `FACE-L`, `FACE-R`, `FACE-B`, `FACE-T` — geometry sets containing each boundary face of the solid. Because the half-hole cutouts break each side into several faces, drag-select with `[Shift]` or use the *by angle* method to grab every face lying on that boundary plane. Only material that actually exists on the plane gets coupled — the hole cutouts are simply absent, which is correct.

## Step 5 — Kinematic couplings (the heart of the model)

**Interaction module** → `Constraint > Create > Coupling`, one per edge. For each: **Control point** = the edge's RP, **Surface** = that edge's face set, **Coupling type: Kinematic**, and check **only** the DOFs in this table:

| Edge | Coupled DOFs (per your procedure) | Left FREE (and why) |
|------|-----------------------------------|---------------------|
| Top (`FACE-T` → `RP-T`) | **UY, UZ**, (URX, URY, URZ) | **UX** free → edge can contract laterally (Poisson) while staying straight in Y |
| Bottom (`FACE-B` → `RP-B`) | **UY, UZ**, (URX, URY, URZ) | **UX** free |
| Left (`FACE-L` → `RP-L`) | **UX, UZ**, (URX, URY, URZ) | **UY** free |
| Right (`FACE-R` → `RP-R`) | **UX, UZ**, (URX, URY, URZ) | **UY** free |

What this does: a kinematic coupling forces each coupled node to move with the RP in the selected DOFs (`u_node = u_RP + θ_RP × r`). Coupling UY on the whole top face forces that edge to **remain straight and move as one** in Y — so the RP's UY *is* the edge displacement, and the RP's reaction force *is* the total edge force. Leaving UX free on the top/bottom edges is what lets the Poisson contraction happen without parasitic shear.

Two practical notes that the procedure write-up glosses over:

> **Corner nodes — Abaqus can error out if you follow the table literally.** Nodes on the corner lines belong to two face sets, and both couplings claim **UZ** (e.g. top coupling and right coupling both constrain DOF 3 of the shared nodes). Abaqus refuses: *"degree of freedom 3 at node X is used by more than one kinematic coupling"*. With the Step-0 region (quarter-holes at the corners) the corner lines sit in the hole voids, so the perforated model may dodge this — but the **solid-plate benchmark in Validation check 1 has real corner nodes and will hit it**, so set the couplings up right from the start. Two clean fixes — pick one:
> 1. **(Simplest, recommended)** Drop **UZ** from the **top and bottom** couplings (couple UY only there; keep UX+UZ on left/right). Out-of-plane rigid motion is still fully restrained through the left/right couplings, and no node is claimed twice. This is the variant shown in the keyword block below.
> 2. Keep the table literally, but remove the shared corner nodes from the top and bottom face sets (`Tools > Set > Edit`, or Boolean the sets). Slightly more bookkeeping, identical results.

> **Rotational DOFs (URX/URY/URZ):** C3D solid nodes have no rotational DOFs, so checking the URi boxes doesn't constrain anything *at the coupled nodes* — the URi entries in your procedure matter only in that the **RP itself** has rotational DOFs, and through the kinematic coupling an RP rotation would sweep the whole edge rigidly about the RP. That is why every RP gets its **rotations fixed to zero as a BC** (Step 7) — otherwise the edge can pivot about the RP as a mechanism (or an unconstrained-DOF warning appears).

The `.inp` this produces (Interaction module writes one block per constraint; `first dof, last dof` per line):

```
*Coupling, constraint name=CPL-R, ref node=SET-RP-R, surface=SURF-R
*Kinematic
1, 1
3, 3
*Coupling, constraint name=CPL-T, ref node=SET-RP-T, surface=SURF-T
*Kinematic
2, 2
```

(CAE converts each face set into an internal surface automatically; left/bottom blocks mirror these. DOF numbering: 1=UX, 2=UY, 3=UZ, 4=URX, 5=URY, 6=URZ.)

## Step 6 — Analysis steps

**Step module**, two general static steps:

1. `Step > Create` → `Step-1-XPULL`, *Static, General*. **Nlgeom: OFF** — the extraction is a linear-elastic small-strain calc (0.1 in on a several-inch region is ~1–2% strain; keep it linear so the extracted constants are the linear-elastic ones). Defaults for incrementation are fine.
2. `Step > Create` → `Step-2-YPULL`, *Static, General*, after Step-1.

## Step 7 — Boundary conditions (per step)

**Load module** → `BC > Create > Displacement/Rotation`, applied **only to the RPs**. Build them in Step-1, then use the **Boundary Condition Manager** to deactivate/activate per the table:

| BC name | RP | DOFs set | Step-1-XPULL | Step-2-YPULL |
|---------|----|----------|--------------|--------------|
| `BC-ROT-UZ-ALL` | all four RPs | `UZ = URX = URY = URZ = 0` | active | active |
| `BC-L-PIN` | `RP-L` | `UX = 0` | active | active |
| `BC-B-PIN` | `RP-B` | `UY = 0` | active | active |
| `BC-R-PULL` | `RP-R` | `UX = +0.1` | **active** | **Deactivated** (right edge free in X → its RP records `Uyx`) |
| `BC-T-PULL` | `RP-T` | `UY = +0.1` | — (not yet created) | **active** (created in Step-2) |

Mechanics of the two load cases:

- **Step 1 (Figure A):** right edge pulled `+0.1 in` in X; left edge held in X; bottom held in Y; **top RP free in UY** → the top edge translates down as a straight line by the Poisson contraction, and its RP's `U2` at the end of Step 1 **is** `Uxy` (expect it negative). The reaction `RF1` at `RP-R` **is** the total axial force `Fx`.
- **Step 2 (Figure B):** the X-pull is deactivated, top edge pulled `+0.1 in` in Y, bottom held; **right RP now free in UX** → its `U1` at the end of Step 2 is `Uyx` (expect negative), and `RF2` at `RP-T` is `Fy`. `RP-L` stays pinned in X purely to prevent rigid-body translation; it carries no net force in Step 2 (good equilibrium check — see Validation).

> **Deactivating `BC-R-PULL` in Step-2 is essential.** If you leave it active you get a biaxial state in Step 2: `Fy` is polluted and `Uyx` cannot be read at all (the right edge is held). In the BC Manager, click the `Step-2-YPULL` cell for `BC-R-PULL` → **Deactivate**.

Keyword check (`Job > Write Input`), Step-2 block should look like:

```
*Step, name=Step-2-YPULL
*Static
1., 1., 1e-05, 1.
*Boundary, op=NEW
SET-RP-L, 1, 1
SET-RP-T, 2, 2, 0.1
** ...UZ/rotation fixes on all RPs re-listed, no SET-RP-R UX line...
```

(CAE writes `op=NEW` and re-lists only the still-active BCs — confirm the `SET-RP-R, 1, 1, 0.1` line is *gone* from Step-2.)

## Step 8 — Mesh

**Mesh module** (on the part, since the instance is dependent):

1. **Element type:** `Mesh > Element Type` → 3D Stress, **C3D8I** (incompatible-modes brick — accurate in-plane behavior at reasonable cost) or **C3D20R** if you prefer quadratic. Avoid plain C3D8R with a coarse mesh for this job (hourglassing + overly soft ligaments), and avoid C3D4 tets.
2. **Seeding:** the accuracy lives in the ligaments. Seed so there are **at least 6–8 elements across the minimum ligament width `b = P − D`**, and 2–4 elements through the 1-in thickness (in-plane loading is uniform through thickness, so through-thickness count is not critical).
3. Hex meshing usually needs partitioning around the holes (`Tools > Partition`); if the pattern makes that tedious, a **C3D8I structured/sweep mesh where possible + well-seeded hex-dominated** mesh is fine for a stiffness (integral) quantity — this is a global-stiffness extraction, not a peak-stress calc, so mesh demands are modest once the ligaments are resolved.
4. `Mesh > Verify` — no analysis errors, warnings reviewed.

## Step 9 — Output requests

**Step module:**

1. `Output > History Output Requests > Create` → domain **Set**, pick `SET-RP-R`: variables `U` (translations) and `RF` (reaction forces), every increment. Repeat for `SET-RP-T`, `SET-RP-L`, `SET-RP-B` (the L/B ones are for the equilibrium checks).
2. Keep the default field output (S, U, E) for contour sanity checks.

## Step 10 — Job

1. `Job > Create` → e.g. `TSP-EQUIV-PROPS`.
2. **Datacheck first** (`Job Manager > Data Check`). Clean up any coupling/overconstraint warnings *now* — the corner-node issue from Step 5 shows up here if a fix wasn't applied.
3. Submit, monitor to completion. Both steps should converge in one increment each (linear problem).

**Visualization module** → `Result > History Output` (or right-click the job → Results). Read values at the **end of the relevant step**:

| Quantity | Where in the ODB | Symbol | Value |
|----------|------------------|--------|-------|

> Because the edge is kinematically coupled, `RF` at the driven RP already **is the sum of all nodal edge forces** — do not go summing nodal forces from field output. Quick equilibrium check while you're here: `RF1(RP-L) = −RF1(RP-R)` in Step 1, `RF2(RP-B) = −RF2(RP-T)` in Step 2.

## Step 12 — Hand calc: equivalent orthotropic constants

All inputs now on the table:

```
Base material:      E = ## psi,   ν = 0.3,   G = E/(2·(1+ν)) = ## psi
Equivalent plate:   Lx = ## in,   Ly = ## in,   Lz = 1 in
Gross areas:        Ax = Ly·Lz = ## in²,  Ay = Lx·Lz = ## in²,  Az = Lx·Ly = ## in²
Net plan area:      A_net,z = Lx·Ly − N_eff·π·D²/4 = ## in²
From the FE run:    Uxx = 0.1 in,  Uxy = ## in,  Uyy = 0.1 in,  Uyx = ## in
                    Fx = ## lbf,   Fy = ## lbf
```

### 12.1 Gross strains of the equivalent plate

```
ε_xx = Uxx / Lx = ##          (axial strain, Step 1)
ε_xy = Uxy / Ly = ##          (transverse strain in Y, Step 1 — negative)
ε_yy = Uyy / Ly = ##          (axial strain, Step 2)
ε_yx = Uyx / Lx = ##          (transverse strain in X, Step 2 — negative)
```

> **Notation (kept from your write-up):** `ε_xy` here is the **transverse normal strain** in Y caused by the X-pull (and `ε_yx` the X-strain caused by the Y-pull) — *not* the engineering shear strain `γ_xy`. Shear doesn't enter until Section 12.5.

> **Denominator note vs your write-up:** a displacement is always divided by the dimension **in its own direction** — `Uxy` is a Y-displacement, so `ε_xy = Uxy/Ly` (your write-up's `Uxy/Lx` is only equivalent when the region is square, `Lx = Ly`). Same for `ε_yx = Uyx/Lx`.

> **Likely typo in the write-up:** `Uyx = −0.5 in` should almost certainly be `−0.05 in` — a transverse contraction can't be 5× the applied pull, and the write-up's own `ν_yx = 0.51` back-calculates from 0.05, not 0.5.

### 12.2 In-plane elastic moduli (gross areas!)

```
Ex = Fx / (Ax · ε_xx) = ## psi
Ey = Fy / (Ay · ε_yy) = ## psi
```

These are the homogenized moduli: gross stress (`F` over the **gross** area) divided by gross strain. The perforation knock-down is now embedded in `Ex/E` and `Ey/E` (each `< 1`; for triangular pitch expect them close to each other but not equal).

### 12.3 Out-of-plane modulus (hand calc)

Out-of-plane (through-thickness) load passes through the net ligament area in plan view. Requiring the equivalent (gross-area) plate to produce the same stiffness as the actual (net-area) material — the `σ = P/A` vs `σ_equiv = P/A_equiv` argument in your write-up, `E_equiv = E·(A/A_equiv)` — gives:

```
Ez = E · (A_net,z / Az) = ## psi
```

(i.e. base modulus scaled by the net-to-gross plan-area ratio.)

### 12.4 Poisson's ratios

In-plane, from the FE run (Poisson's ratio is defined with a minus sign; the transverse strains are negative, so the ratios come out positive):

```
ν_xy = −ε_xy / ε_xx = ##        (write-up example: 0.51)
ν_yx = −ε_yx / ε_yy = ##        (write-up example: 0.51)
```

> A value **above 0.5 is not an error** for a perforated plate. The equivalent material is a *structure* homogenized into a continuum — the incompressibility bound ν ≤ 0.5 applies to isotropic solids, not to effective orthotropic constants. Values of 0.4–0.7 are routine for perforated patterns.

Out-of-plane: a through-thickness stress works on the base material, so the lateral contraction it drives is the base material's:

```
ν_zx = ν = 0.3          ν_zy = ν = 0.3
```

and the reciprocal pair follows from the symmetry (Maxwell) relation `ν_ij/Ei = ν_ji/Ej`:

```
ν_xz = ν_zx · (Ex / Ez) = ##        (write-up example: 0.07)
ν_yz = ν_zy · (Ey / Ez) = ##        (write-up example: 0.07)
```

**Consistency check (do it):** the same Maxwell relation must hold in-plane: `ν_xy/Ex ≈ ν_yx/Ey`, i.e. `ν_xy·Ey ≈ ν_yx·Ex`. Your two FE load cases measure both sides independently, so this is a free quality check on the model. Small differences (a few %) are normal — Abaqus only accepts one value (`ν_xy`), so if they differ, carry the pair that satisfies the relation with your chosen `Ex, Ey` (e.g. keep the measured `ν_xy` and note that `ν_yx` is then implied).

### 12.5 Shear moduli

Base material: `G = E/(2·(1+ν)) = ##` psi.

**In-plane `Gxy`** — two options:

- **Option A (recommended when the schedule allows): a third FE load case.** Copy the model; change the couplings so top/bottom edges couple **UX** (tangential) as well as UY; fix the bottom RP (`UX = UY = 0`), hold top RP `UY = 0` and apply `UX = +0.05 in`; leave left/right faces uncoupled/free. Then

  ```
  γ_xy = U_shear / Ly = ##
  τ_xy = RF1(RP-T) / (Lx · Lz) = ## psi
  Gxy  = τ_xy / γ_xy = ## psi
  ```

- **Option B (closed-form estimate, common in procedures like yours):** use the orthotropic analog of the isotropic relation, built from the constants you already have:

  ```
  Gxy ≈ √(Ex·Ey) / (2·(1 + √(ν_xy·ν_yx))) = ## psi
  ```

  This is an approximation (the true `Gxy` of a perforated pattern is an independent property); flag it as such in the calc note, or anchor it against Option A / the ASME A-8000 effective-constant curves once.

**Out-of-plane `Gxz`, `Gyz`:** same net-area logic as `Ez` — through-thickness shear is carried by the ligament area:

```
Gxz = Gyz = G · (A_net,z / Az) = ## psi
```

(Your write-up lists the full set `Gxy, Gyx, Gxz, Gzx, Gyz, Gzy` — shear moduli are symmetric, `Gxy = Gyx` etc., so only the three independent values above go into Abaqus.)

## Step 13 — Enter the equivalent material in Abaqus

In the full-TSP model — **Property module** → `Material > Create` → `Mechanical > Elasticity > Elastic`, **Type: Engineering Constants**. Abaqus's 1-2-3 axes map to your X-Y-Z:

| Abaqus field | Your constant | Value |
|--------------|---------------|-------|
| `E1` | `Ex` | `##` psi |
| `E2` | `Ey` | `##` psi |
| `E3` | `Ez` | `##` psi |
| `Nu12` | `ν_xy` | `##` |
| `Nu13` | `ν_xz` | `##` (the **small** one, ~0.07 — *not* ν_zx = 0.3) |
| `Nu23` | `ν_yz` | `##` (small one) |
| `G12` | `Gxy` | `##` psi |
| `G13` | `Gxz` | `##` psi |
| `G23` | `Gyz` | `##` psi |

Keyword block produced:

```
*Elastic, type=ENGINEERING CONSTANTS
Ex, Ey, Ez, nu_xy, nu_xz, nu_yz, Gxy, Gxz
Gyz
```

Three things to get right here:

1. **ν convention.** Abaqus defines `Nu_ij = −ε_jj/ε_ii` for a stress applied in direction *i*, and requires the entries `Nu12, Nu13, Nu23` (it derives `Nu21` etc. from `ν_ji = ν_ij·Ej/Ei`). That means the *xz* slot takes your **ν_xz ≈ 0.07**, not ν_zx = 0.3. Entering 0.3 there is the classic mistake and badly stiffens the through-thickness coupling.
2. **Stability checks.** Abaqus enforces material stability: `ν_12 < √(E1/E2)`, `ν_13 < √(E1/E3)`, `ν_23 < √(E2/E3)`, and `1 − ν12·ν21 − ν23·ν32 − ν31·ν13 − 2·ν21·ν32·ν13 > 0`. With `Ex ≈ Ey`, `ν_xy ≈ 0.51 < √(Ex/Ey) ≈ 1` passes fine. If datacheck rejects the material, re-check the Maxwell consistency of your set before touching the numbers.
3. **Material orientation.** Engineering constants are meaningless without an orientation. Assign one (`Assign > Material Orientation`) on the TSP region so that **local 1 = the hole-row direction (your X)** and local 3 = plate normal. If the TSP is meshed with its pattern aligned to the global axes, the default (global) orientation is fine — but assign it explicitly anyway so the deck documents the intent (`*Orientation` + `*Solid Section, orientation=...`).

> Scope reminder: these constants homogenize the **in-plane membrane stiffness** (plus the hand-calc out-of-plane values). A solid-element TSP with these constants will also bend with them; for a perforated plate the effective *bending* stiffness knock-down is not identical to the membrane one. For TSP support-stiffness purposes (in-plane tube-support loads) this is the standard approach — just don't re-use the same constants for a lateral-pressure plate-bending qualification without checking (ASME A-8000 provides bending-specific effective constants).

## Variant — S4R shell extraction model

**Is S4R appropriate? Yes — for the 1-in plate.** Both load cases are pure in-plane membrane pulls, and the membrane response of a shell *is* the plane-stress problem this extraction is built on. S4R (4-node linear, reduced integration, hourglass-controlled, general-purpose shell) works with two cautions specific to it:

1. **Reduced integration → hourglassing.** S4R has a single in-plane integration point, so a coarse mesh under membrane load can hourglass. The ligament seeding rule (6–8 elements across `b = P − D`) already protects you; verify by checking that artificial strain energy is negligible — history output `ALLAE / ALLIE < ~1–2%` (whole-model energy history is on by default). If you'd rather not think about it at all, use fully integrated **S4** — this model is small, the cost difference is nothing.
2. **Shell nodes have real rotational DOFs.** Unlike C3D solids, the URi boxes in the coupling table now actually constrain the nodes. Leave rotations **out** of the couplings (translations only, per the table); keep the RP rotations fixed to zero exactly as in Step 7. Don't couple the drilling DOF (URZ); default drill stiffness is fine.

**Everything else carries over.** The deltas against the solid walkthrough:

| Item | 3D solid (main walkthrough) | S4R variant |
|------|-----------------------------|-------------|
| Part | 3D solid extrusion, 1 in | 3D **planar shell** part sketched in X-Y (the midsurface); identical hole-pattern sketch, holes cut in the sketch |
| Section | Solid, homogeneous | **Homogeneous shell section**, thickness `Lz`, material `TSP-BASE` (default Simpson integration fine) |
| Edge sets (Step 4) | 4 boundary *faces* | 4 boundary *edges* (each broken into segments by the half-holes — select all segments on the boundary line) |
| RPs (Step 3) | mid-edge, mid-thickness `z = 0.5` | mid-edge in the midsurface plane, `z = 0` |
| Couplings (Step 5) | DOF table as written | **Same table** — top/bottom couple UY; left/right couple UX + UZ; same corner-node logic; URi unchecked |
| Element (Step 8) | C3D8I, 2–4 through thickness | **S4R** (or S4), in-plane seeding rule unchanged, no thickness direction to mesh |
| Steps, BCs, outputs (6, 7, 9) | as written | identical |
| Extraction + formulas (11, 12) | as written | **identical** — `RF1` at `RP-R` is already the through-thickness-integrated edge force, so `Fx/(Ax·ε_xx)` with `Ax = Ly·Lz` works unchanged |

Notes on what the shell variant means physically:

- The shell thickness only scales the section stiffness linearly, so the extracted knock-downs `Ex/E`, `Ey/E`, `ν_xy` are **independent of the thickness value** — they are properties of the 2D hole pattern under plane stress.
- S4R gives you **nothing out-of-plane**: `Ez, ν_xz, ν_yz, Gxz, Gyz` remain the Step 12.3–12.5 hand calcs, unchanged.
- The **solid-plate benchmark** (Validation check 1) applies verbatim and is just as mandatory — a no-hole S4R model must return `E` and `ν = 0.3`. Note the benchmark plate *does* have corner nodes, so the corner-UZ coupling fix from Step 5 matters here too.
- If your **full TSP model** is S4R shells with the equivalent material: a conventional shell enforces plane stress, so it uses `E1, E2, Nu12, G12` for membrane/bending and `G13, G23` for transverse shear — `E3, Nu13, Nu23` are accepted in the material definition but not used. Enter the full 9-constant set anyway (documents the calc, and lets you switch to solids later). Be aware a shell TSP has **no through-thickness bearing stiffness** — if tube-to-TSP bearing matters, that load path isn't in the shell model.

## How thick can the plate be? (1 in vs 11 in)

**The process itself doesn't change with thickness.** Region choice, couplings, the two-step pull, and every formula in Step 12 are thickness-blind — for an 11-in plate you extrude the solid 11 in, set `Lz = 11` everywhere it appears (`Ax`, `Ay`, `Az`, shear areas), and proceed. The in-plane knock-down factors are 2D pattern properties and come out essentially the same. What changes is **which elements are appropriate**, in two separate places:

**1. The extraction model.** A shell (or plane-stress) extraction assumes plane stress through the thickness — good when the thickness is comparable to the pitch (your 1-in plate with ~1-in pitch: fine). When `t/P >> 1` (11-in plate, ~1-in pitch → `t/P ≈ 11`), the ligament interior is constrained toward **plane strain**, and the plane-stress assumption starts to misstate the effective in-plane constants (the shift is bounded by ν²-type factors, `1/(1−ν²) ≈ 1.10` — modest, but real, and a thick-tubesheet reviewer will expect the thick-plate treatment). So:

- **11 in thick → use the 3D solid extraction model** (the main walkthrough, unchanged — just the deeper extrusion, 4+ elements through thickness), which captures the through-thickness constraint automatically; **or** a 2D **generalized plane strain** (CPEG) model of the region, which is the classical thick-plate analog of the plane-stress model.
- This thin/thick distinction is the same one the effective-elastic-constant literature makes (O'Donnell & Slot — the basis of ASME Appendix A-8000 — treat plane stress and generalized plane strain separately), so the A-8300 cross-check in Validation still applies at 11 in.

**2. The full TSP model that receives the equivalent material.** S4R is a general-purpose shell with transverse shear flexibility and stays credible down to a span-to-thickness ratio of roughly **10–15**. An 11-in-thick plate qualifies only if its lateral span is well beyond ~110–160 in; for a typical TSP/tubesheet diameter it does not — model the 11-in plate with **continuum solids** (C3D8I / C3D20R) carrying the full 9-constant orthotropic set. That is the standard thick-tubesheet approach, and it's also the only way the through-thickness constants (`Ez`, `Gxz`, `Gyz`, `ν_xz`, `ν_yz`) you calculated actually participate. If you are at the shell margin and stay with S4R, note the transverse shear response comes from your `G13`/`G23` entries — so the net-area-reduced `Gxz`, `Gyz` values matter, don't leave base-material values there.

Bottom line: **1 in thick → S4R is appropriate for both the extraction model and (with the plane-stress caveats above) the full plate. 11 in thick → same process, but extract with solids and build the full model with solids.**

## Step 14 — Validation

Run these in order; each one is cheap and catches a different failure mode.

1. **Solid-plate benchmark (run this before the perforated model).** Suppress the hole cut feature (or build a copy without it) and run the identical two-step analysis. With the couplings/BCs correct, the state is uniform uniaxial plane stress and the extraction must return `Ex = Ey = E` and `ν_xy = ν_yx = 0.3` to within a fraction of a percent. If it doesn't, the couplings/BCs are wrong — fix them *before* looking at any perforated result. (Common culprits: a UZ over-constraint stiffening the edges, a distributing coupling instead of kinematic, or `BC-R-PULL` still active in Step 2.)
2. **Equilibrium.** `RF1(RP-L) = −RF1(RP-R)` at end of Step 1; `RF2(RP-B) = −RF2(RP-T)` at end of Step 2; and in Step 2 the X-reactions at `RP-L` should be ~0. Non-zero residuals mean a load path you didn't intend (usually a leftover BC).
3. **Reciprocity.** `ν_xy·Ey ≈ ν_yx·Ex` (Section 12.4). Disagreement beyond a few percent usually means the region isn't pattern-symmetric (boundaries not on symmetry lines) or the mesh is too coarse in the ligaments.
4. **Mesh convergence.** Double the seeds (especially across the ligaments) and re-run: `Fx`, `Fy`, `Uxy`, `Uyx` should move by < 1–2%. The stiffness converges much faster than peak stress, so one refinement level normally settles it.
5. **Literature cross-check.** For a triangular penetration pattern, ASME Section III Appendix **A-8000** (Article A-8300) tabulates effective elastic constants `E*/E` and `ν*` versus ligament efficiency `η = (P−D)/P`. Look up your `η = ##` and confirm your `Ex/E`, `Ey/E`, `ν_xy` sit in the same neighborhood. They won't match exactly (A-8000's constants are derived for a specific stress state and include bending considerations), but an order-of-magnitude disagreement means a units or area error.
6. **Round-trip check (closes the loop).** Build a plain rectangular solid `Lx × Ly × 1 in` with **no holes**, assign the equivalent orthotropic material from Step 13, apply the *same* couplings, steps, and BCs, and re-run. It must reproduce your perforated model's `Fx`, `Fy`, `Uxy`, `Uyx` (in-plane values essentially exactly; small differences only from the ν_xy/ν_yx rounding decision). This proves the constants you typed into Abaqus actually encode the behavior you extracted.

## Common pitfalls

- **Corner nodes claimed by two kinematic couplings (UZ)** → fatal error at datacheck. Fix per Step 5: drop UZ from the top/bottom couplings, or remove shared corner nodes from two of the face sets.
- **Distributing coupling instead of kinematic.** A distributing coupling only ties the edge *on average* — the edge won't stay straight, the reaction is redistributed, and the extracted moduli drift. This procedure requires **kinematic**.
- **RP rotations left free.** The kinematic coupling makes RP rotation sweep the whole edge rigidly; unconstrained RP rotations are a mechanism. `UZ = URX = URY = URZ = 0` on all four RPs, both steps.
- **Forgetting to deactivate the Step-1 pull in Step-2** → biaxial state, wrong `Fy`, and no `Uyx` to read.
- **Net vs gross area mix-ups.** `Ex`, `Ey` use **gross** areas (`Ax = Ly·Lz`, `Ay = Lx·Lz`); only `Ez`, `Gxz`, `Gyz` use the net/gross plan-area ratio. Mixing these double-counts the perforation.
- **Wrong transverse denominator.** `ε_xy = Uxy/Ly`, not `/Lx` (matters as soon as the region isn't square).
- **Entering ν_zx (0.3) into Abaqus's Nu13 slot.** Abaqus wants `Nu13 = ν_xz` (~0.07). See Step 13.
- **Signs.** `Uxy`, `Uyx` come out of the ODB negative; the Poisson definition carries the minus sign, so the ratios are positive. Don't drop *and* re-add the sign.
- **ν_xy > 0.5 panic.** Legitimate for homogenized perforated plates (see 12.4). Abaqus's orthotropic stability limit is `ν12 < √(E1/E2)`, not 0.5.
- **Region boundaries off the pattern symmetry lines.** If an edge slices holes asymmetrically, the straight-edge coupling fights the pattern and biases the result — re-cut the region per Step 0.
- **Reading edge force from field output.** Use `RF` at the RP from history output — it is already the total edge force by virtue of the coupling.
- **S4R variant specifics.** Coarse reduced-integration meshes hourglass under membrane load — keep the ligament seeding rule and check `ALLAE/ALLIE < ~1–2%` (or use S4). And shell nodes *do* carry rotational DOFs, so URi boxes in the couplings are live constraints there — couple translations only.
- **Shells for a thick plate.** Below a span-to-thickness ratio of ~10–15 (e.g. an 11-in-thick plate of ordinary TSP diameter), conventional shells misrepresent the plate — extract with solids and assign the equivalent material to a solid full model. See "How thick can the plate be?".
